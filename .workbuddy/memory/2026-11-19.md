## 社区脚本「家宽识别」评估（仅分析，未改仓库文件）
- 来源：`https://raw.githubusercontent.com/IvanSolis1989/Smart-Config-Kit/main/Mihomo内核系/FlClash/FlClash(mihomo).js`，v6.0.21-flclash.26，1711 行 / 158KB，架构 22 url-test 区域组（11 全部 + 11 家宽）+ 33 业务组 + 149 规则源。
- **家宽识别 = 纯节点名关键词，无任何出口 IP / ASN / hosting 探测**。模块 A `RESIDENTIAL_PATTERNS` 10 条：`家宽|家庭宽带|家庭住宅|住宅宽带|住宅|宽带`、`\bresi(?:dential)?\b`、`\bhome...ip\b`、`\bhome...broadband\b`、`\bhome\b`、`\bbroadband\b`、`\bisp\b`、`\biplc\b`、`\biepl\b`、`专线`；`isResidentialNode()` 用 `.some()` 任一命中即 true。即作者把 IEPL / IPLC / 专线 / ISP 都归为「住宅级线路」，是营销词分类而非真住宅 IP 判定。
- 分类流程：`classifyAllNodes()` 先滤伪节点 → `isHome` 布尔 + `classifyNode()` 11 地区 → `HOME_<region>` 二维桶；`upsertUrlTestGroup()` 只在桶非空时建组（`v5.2.8-normal.2` 起空组不建）；`withResidential()` / `buildHomeFirstProxies()` 让业务组把家宽组排在全部组前面。
- **用用户真实订阅实测（90 行，含 2 个信息伪节点）**：88/88 真节点全部被判为家宽，命中来源 100% 是 `\biepl\b` 与 `专线`；中文「家宽/住宅/宽带」、`home`、`residential`、`isp` 命中全为 0。即「家宽组」与「地区组」几乎完全重合，照搬该规则在本订阅上无区分意义。
- 订阅里真正有信息量的维度是线路等级：**实验性 4 / 标准 69 / 高级 15**；另有 `IEPL` 88、`专线` 88。若要建有价值的线路组，应按这个标签分，而不是「家宽」。
- 我们的脚本支持情况：主线 `scripts/build.js` 的 `REGION_GROUPS`（11 条）+ 两种建组模式（内联 `mihomoKitMatch()`、provider `include-all + filter`/`exclude-filter`）完全可扩展；加 1 个全局家宽组只需数据区加一条，加「地区 × 家宽」11 组需在 431-452 的循环里组合 filter，再进 `strategyOptions`（456-457）。OneSmart 适配版 `dist/mihomo-rule-onesmart.js` 本来就有 `家宽-智能`/`家宽-手选`，但 `FilterJK = (?i)家宽` 严格匹配 → 0 命中 → 被自适应裁剪移除。
- 结论/建议：技术上能支持，但当前订阅没有真实住宅 IP 标识，照搬社区宽松规则只会得到「家宽 = 全部」。真家宽需要探测出口 IP 的 ASN 类型，覆写脚本期拿不到（只有节点名）。已向用户给出三选项：保持现状 / 照搬宽松规则 / 改按线路等级（实验性·标准·高级）建组，等用户选择后再动手。
